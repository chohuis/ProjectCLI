# 개발 환경

## 개발 기준

| 항목 | 기준 |
| --- | --- |
| 대상 플랫폼 | PC, 우선 Windows에서 개발·검증 |
| 언어 | C# |
| SDK | .NET 10 LTS |
| 그래픽 엔진 | Godot 4.6.1 .NET판 |
| 편집기 | VS Code + C# Dev Kit |
| 자동 테스트 | xUnit |
| 콘텐츠 관리·배포 형식 | 개발 초기부터 암호화된 `.dat` |
| 세이브 형식 | 암호화된 JSON `.dat`과 SQLite 비교 후 확정 |
| 내부 직렬화 | `System.Text.Json`으로 메모리에서 JSON 변환 |
| 콘텐츠 암호화 | .NET 기본 라이브러리의 AES-GCM |
| 버전 관리 | Git + GitHub |

## 버전과 호환성

- 검증한 SDK의 정확한 버전은 `global.json`으로 고정한다.
- 패키지 버전은 프로젝트 설정에 명시한다.
- .NET SDK 버전과 프로젝트의 대상 프레임워크는 구분한다. 대상 프레임워크는 공통 C# 라이브러리의 Godot 연동 및 Windows 내보내기 검증 후 확정한다.
- C# 그래픽 버전 개발에는 Godot 일반판이 아닌 **.NET판**을 사용한다.

## CLI 개발·실행 조건

- CLI는 일반 .NET 콘솔 프로그램으로 개발하며, 자체적으로 완성된 게임으로 구현한다.
- CLI와 공통 게임 로직은 Godot 엔진·전용 SDK·패키지·타입에 의존하지 않는다.
- CLI 개발·빌드와 자동 테스트에는 .NET SDK가 필요하고, Godot는 필요 없다.
- CLI 실행에는 대상 버전에 맞는 .NET 런타임이 필요하다. 자체 포함 배포를 선택하면 실행 PC에 별도 .NET 설치 없이 구동할 수 있다.
- Godot는 이후 그래픽 버전의 개발·빌드에 사용한다.

## 전체 구성

구성도와 요청별 실행 흐름의 기준은 [코드 구조](코드_구조.md)에 둔다.

- 실행 중의 규칙 계산은 C# 메모리 데이터로 수행한다. JSON과 저장 파일은 읽기·쓰기 경계에서 처리한다.
- 콘텐츠의 기준 파일은 개발 초기부터 암호화된 `.dat`으로 관리한다. 평문 JSON 파일을 콘텐츠 원본으로 유지하지 않고, JSON은 메모리의 직렬화 표현으로 사용한다.
- 저장·불러오기와 암호화 기능도 Godot에 의존하지 않는 .NET 코드로 구현하여 CLI와 그래픽 버전에서 재사용한다.
- 콘텐츠는 배포물에서 읽고, 세이브는 사용자별 쓰기 가능한 데이터 경로에 보관한다. CLI와 Godot에 공통 경로 정책을 적용하며, 구체적인 경로는 추후 확정한다.

## 콘텐츠 저장 기준

- 첫 콘텐츠 작성부터 암호화된 `.dat`을 사용한다. 개발과 배포에서 동일한 파일 형식과 읽기·쓰기 코드를 사용한다.
- `.dat`은 파일 확장자다. 내부 데이터는 JSON으로 직렬화한 뒤 AES-GCM으로 암호화한다.
- 콘텐츠 생성·조회·수정 도구를 초기 개발 범위에 포함한다. 파일을 복호화하여 메모리에서 편집하고, 검증 후 JSON 직렬화·암호화를 거쳐 `.dat`으로 저장한다. 편집을 위한 평문 JSON 중간 파일은 기본 흐름에 만들지 않는다.
- 읽기는 파일 구조 확인 → 인증 태그 검증·복호화 → JSON 해석 → 값과 참조 관계 검증 순서로 처리한다. 인증 실패나 지원하지 않는 형식은 게임 상태에 반영하지 않는다.
- 같은 키에서 nonce가 재사용되지 않도록 생성·관리한다. 키 제공·보관·배포 정책은 첫 저장 기능 구현 전에 정하고, 실제 비밀 키를 Git에 커밋하지 않는다.
- 파일 형식 버전과 데이터 스키마 버전을 관리하고, 해석에 영향을 주는 헤더는 인증 범위에 포함하도록 설계한다.
- 저장은 임시 파일에 작성·검증한 뒤 기존 파일을 교체하고 이전 정상 저장본을 보존하는 방식으로 설계한다.
- 오프라인 클라이언트의 암호화는 일반적인 열람·편집 억제와 변조 탐지를 목표로 하며, 분석·우회를 완전히 차단한다고 가정하지 않는다.
- 게임 콘텐츠를 대량 작성하기 전에 생성·수정·다시 불러오기, 파일 변조·잘못된 키·버전 거부, 저장 실패 후 복구를 자동 테스트로 확인한다.

콘텐츠 저장 방식은 위 기준으로 선택했으며, 아직 구현·성능 검증되지 않았다.

## 세이브 형식 검토

- 이번 결정은 기본 콘텐츠에 적용한다.
- 세이브에도 암호화된 JSON `.dat`을 적용할 수 있으나, 누적 기록의 규모·조회·저장 비용을 검토하여 SQLite와 비교 후 결정한다. SQLite를 채택할 경우 암호화 및 백업 정책도 별도로 설계한다.

## 환경 준비 상태

개발 기준의 선택과 실제 환경 설정 완료는 구분한다. 현재 .NET 10 및 실제 프로젝트 검증은 완료되지 않았다. 설치·검증 결과와 착수 단계별 남은 준비의 기준은 [환경 검증](../04_검증/환경_검증.md)에 둔다.
