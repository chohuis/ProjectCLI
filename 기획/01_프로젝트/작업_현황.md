# 작업 현황

관리 책임: 총괄. 담당자는 작업 ID에 연결된 결과를 보고하고 총괄이 공통 현황을 갱신한다.

## 현재 작업

| 작업 ID | 작업 | 담당 | 상태 | 기준·결과 |
| --- | --- | --- | --- | --- |
| TASK-0001 | 합의된 개발·운영 규칙 문서화와 환경 준비 검토 | 총괄·기획·QA | 완료 | 10개 문서 링크 확인 및 문서 QA 통과. [개발 규칙](개발_규칙.md), [운영 체계](운영_체계.md), [환경 검증](../04_검증/환경_검증.md) |

TASK-0001의 문서 작성·읽기 전용 환경 점검·문서 QA는 완료했다. SDK 설치, 게임 코드·프로젝트 생성, 암호화 구현은 포함하지 않는다. 승인된 구체 API는 아직 없어 이 작업의 기준 계약 버전은 해당 없음이다. 사용자가 요청한 커밋·push는 총괄의 전달 단계로 수행하며 성공 여부는 Git 이력·원격 상태와 최종 보고에서 확인한다.

## 이번 검증 결과

| 이슈 ID | 관련 작업 | 내용 | 결과 |
| --- | --- | --- | --- |
| QA-0001 | TASK-0001 | 코드 구조의 저장 경로가 세이브 암호화를 확정한 것처럼 표현됨 | 콘텐츠의 AES-GCM과 미정 세이브 정책을 구분하도록 수정, QA 재검증 후 종료 |

문서 QA는 역할·승인 경계, 단일 기준, 계약 변경 절차, 콘텐츠·세이브 구분, 미구현·미검증 상태를 확인했다. 게임 빌드·실행 검증은 수행하지 않았다.

## 다음 작업 후보

아래는 아직 배정·착수하지 않은 준비 목록이다. 총괄이 범위와 완료 조건을 정한 뒤 작업 ID를 부여한다.

| 우선 시점 | 준비할 내용 | 완료 조건의 예 |
| --- | --- | --- |
| CLI 기반 개발 전 | .NET 10 SDK 설치·고정, 프로젝트·서식·검사 설정 | 선택한 SDK에서 CLI 빌드·실행과 xUnit 실행 확인 |
| 병렬 구현 전 | 공용 요청·응답·상태 소유권·오류 계약 | 기획의 기대 동작과 총괄의 승인 계약 전달 |
| 첫 콘텐츠 파일 구현 전 | `.dat` 형식·키 정책·관리 도구 계약 | 생성·편집·저장·로드·실패 복구를 검증할 명세 |
| 세이브 기능 구현 전 | 세이브 저장 방식과 기록 보존 범위 | 복원 대상·버전·호환·백업 기준 확정 |
| Godot 착수 전 | .NET판 준비·공통 라이브러리 연동 | 참조·실행·Windows 내보내기 확인 |

## 기록 규칙

- ID는 `TASK-0001`, `CHANGE-0001`, `QA-0001`처럼 종류별 순서로 부여한다. 단순한 할 일에 불필요한 변경·QA ID를 추가하지 않는다.
- 작업에는 목표, 수정 범위, 기준 명세·계약·커밋, 완료 조건, 결과를 연결한다.
- 변경 요청과 QA 이슈는 관련 작업 ID에 연결한다. 긴 설명은 관련 명세·결정·검증 문서의 해당 절에 두고 현황에는 링크만 남긴다.
- 중요한 승인에는 승인 주체·날짜·결정·영향 범위·후속 작업을 남긴다.
- 커밋을 만드는 문서에 그 커밋 자신의 해시를 쓰지 않는다. 커밋 목적과 Git 이력으로 추적하고, 후속 작업의 기준에는 실제 기존 커밋을 기록한다.
