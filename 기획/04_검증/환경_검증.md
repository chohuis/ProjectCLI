## CLI 기반 개발 전 준비

1. .NET 10 LTS SDK 설치 후 사용할 정확한 버전을 정하고 `global.json`으로 고정한다.
2. 공통 로직·실행 관리·CLI·저장·테스트의 실제 프로젝트 분할과 대상 프레임워크를 정한다. Godot 참조 가능성은 작은 호환성 확인으로 검토하되 CLI의 Godot 독립성을 유지한다.
3. `.editorconfig`, nullable·분석기 설정, `.gitignore`를 구성한다. 빌드 산출물·개인 설정·실제 키·임시 파일이 추적되지 않게 한다.
4. 패키지 소스와 정확한 버전을 정하고, CLI 실행·xUnit 실행·VS Code 디버깅을 확인한다. 사용할 명령을 재현 가능하게 기록한다.
5. 첫 실행 가능한 코드가 생기면 Windows 기준 빌드·테스트 CI를 연결한다. 문서 전용 현재 커밋에 실행 가능한 CI가 있다고 가정하지 않는다.
6. 병렬 구현 전 담당 파일과 공용 계약·기준 커밋을 배정한다.

## Godot 개발 전 준비

- Godot 4.6.1 .NET판과 필요한 내보내기 템플릿 준비.
- 공통 라이브러리 참조·호환 대상 프레임워크·실행 확인.
- Windows 내보내기와 내보낸 실행 파일 확인.
- CLI와 그래픽 버전이 공통 콘텐츠·저장 정책을 사용할 수 있는지 확인.

Godot 설치는 CLI 독립 개발·실행의 필수 조건이 아니다. 전체 GUI와 게임 세부 시스템의 설계도 CLI 기반 환경 설정의 완료 조건으로 두지 않는다.

## 도구 실행 관련 확인 사항

- 현재 샌드박스에서는 `.git` 쓰기와 네트워크 접근에 제한이 있을 수 있다. 이전 commit/push는 승인된 실행으로 완료했다.
- 승인된 실행 사용자와 저장소 소유자 차이로 Git 소유권 검사가 발생했다. 해당 저장소를 명령 범위의 `safe.directory`로 지정해 처리했고 전역 예외는 추가하지 않았다.
- 이전 .NET SDK 초기화에서 워크로드 안내가 있었으나 일반 콘솔 빌드·실행은 성공했다. .NET 10 환경에서 다시 확인한다.
- 제한된 실행에서 전역 Git ignore 읽기 경고가 있었다. 사용자 실행 권한·프로젝트 ignore 설정을 구분해 확인한다.
