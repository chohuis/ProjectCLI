# 0001. 개발 기준과 AI 운영 체계

상태: 사용자 합의 반영. 결정일: 2026-10-30. TASK-0001에서 문서화.

## 배경

CLI 자체를 완성된 정치 시뮬레이션 게임으로 개발하고 이후 Godot에서 그래픽 버전으로 확장한다. 여러 AI가 작업해도 공용 인터페이스와 데이터 형식을 임의 변경하지 않도록 책임과 승인 기준이 필요하다.

## 결정과 이유

| 결정 | 이유·영향 |
| --- | --- |
| C# 공통 로직과 독립 CLI, 이후 Godot .NET | 검증된 규칙과 저장 기능을 재사용하고 표현 계층을 구분 |
| 기본 콘텐츠는 최초 작성부터 암호화 `.dat` | 실제 파일 형식과 편집·읽기·실패 처리 문제를 초기에 검증 |
| 내부 JSON 직렬화와 AES-GCM | 표준 라이브러리로 데이터 변환과 인증 암호화를 구현 |
| 총괄과 기획을 분리한 6개 역할 | 요구 동작 정리와 기술 승인·통합 책임을 구분 |
| 공용 계약 변경은 총괄 승인 | 인자·반환·동작·오류·스키마의 독단적 변경 방지 |
| 계약 중심·가벼운 도메인 설계·계층 분리·핵심 테스트 | AI 간 해석 차이를 줄이면서 불필요한 구조 방지 |
| 공통 작업 ID와 단일 기준 문서 | 역할별 중복 일지와 서로 다른 명세 방지 |

현재 기준은 [개발 환경](../03_기술_설계/개발_환경.md), [개발 규칙](../01_프로젝트/개발_규칙.md), [운영 체계](../01_프로젝트/운영_체계.md)에 둔다. 이 기록은 선택의 배경을 보존하며 상세 명세를 중복 관리하지 않는다.

## 미정 및 검증 필요

정확한 SDK·패키지 버전과 대상 프레임워크, 구체 API, 키 정책·파일 스키마, 세이브 형식, 게임 세부 규칙은 미정이다. .NET 10·xUnit·Godot 연동과 `.dat` 기능은 미검증이다. [환경 검증](../04_검증/환경_검증.md)을 따른다.

## 재검토 조건

Godot 호환성 문제, 실제 콘텐츠·기록의 크기와 조회·저장 비용, 개발 도구 사용성 문제, 사용자 요구 변경이 확인되면 영향과 대안을 제안한다. 기존 결정은 삭제하지 않고 후속 승인 기록으로 대체한다.
